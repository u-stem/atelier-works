# Consoleの画面の表示の原則

Consoleの画面に、表示を足すか残すかを決める原則を定める。
画面を作る人、直す人、レビューする人が読む。
画面ごとの仕様は[Consoleの仕様](internals/console.md)にある。

運用者はConsoleを毎日開く。
判断につながらない表示は、毎日読み飛ばす行になり、読むべき行を埋める。
そのため、表示は足す前に要るかを確かめ、要らないものを削る。

## 表示の要素ごとに問うこと

見出し、数字、時刻、ラベル、注記、ボタンを、画面の要素と呼ぶ。
要素ごとに、次の3つを問う。

1. 誰が、いつ見るか。
2. 見て何を決めるか。
3. 同じ情報が別の場所に無いか。

1か2に答えられない表示は、判断につながらない。
3が「ある」表示は、重複である。
どちらもノイズなので、削る。

## 情報の置き場所

3つ目の問いは、次の表に照らして決める。
表の「情報」を出す要素が「置き場所」以外にあれば、重複である。
表に無い情報を出すときは、表に1行足し、置き場所を1か所に決める。

| 情報 | 置き場所 | 本体に置かないもの |
| --- | --- | --- |
| 要対応の件数 | サイドバーの要対応の入口のバッジ。幅が狭いときは、メニューのボタンの点と名前 | 見出しや案内文での、同じ件数の繰り返し |
| 最終更新の時刻と更新の操作 | 画面の見出しの右に1組。複数の取得を持つ画面は、取得できた中で最も古い時刻 | 帯や節ごとの取得の時刻 |
| 自動更新の間隔 | 最終更新の脇 | 帯や節ごとの間隔の注記 |
| 一覧の件数 | 件数を持つタブは、タブの名前。タブが件数を持たない一覧は、一覧の上 | タブの名前と同じ数を、本体の見出しや先頭の文で繰り返すこと |
| 画面の見出し | 画面の見出し(h1)の1つ | タブの名前と重なる見出し |
| タブの中の注意と取得の失敗 | タブの名前の印 | 同じ印を、本体の別の場所に重ねること |
| 判定の段(正常、注意、要対応) | システムの画面は、要約の帯のチップとタブの印 | 同じ判定を、別の語や形で言い換えること |
| 配信している版と取り込みの状態 | サイドバーの下部 | 本体での版の表示 |
| ログイン切れ、Windmillに届かない | 画面の上部の帯 | 各節での同じ内容の警告 |
| 取得の失敗 | 失敗した表や節の位置。前の値を出し続けるときは、その節の知らせ | 画面全体に重ねる別の失敗の表示 |
| 状態、種別、ジョブへのリンク | それが起きた行の中 | 行の外の要約での、同じ状態の繰り返し |

## 削らないもの

次の表示は、3つの問いに答えられるので、削る対象にしない。

- 失敗の表示。
  取得の失敗、前の値であることの知らせ、判定の注意と要対応が当たる。
  運用者が異常に気づけなくなるためである。
- 読み上げ専用の語。
  画面に見えず、読み手の邪魔にならないためである。
- 取り消せない操作の確認。
  誤操作を元に戻せないためである。

ただし、これらも置き場所の表に従い、位置は寄せる。

## 隠れない条件のために表示を足すとき

失敗や古い値を隠さないために、表示を足したくなることがある。
足す前に、次の順で考える。

1. 既存の場所の値や印を変えて満たせないかを考える。
   例えば、古い節が新しく見えないようにするには、見出しの最終更新を最も古い時刻にする。
   タブに隠れた失敗は、タブの名前の件数と印で示す。
2. 満たせないときだけ、異常のときに出る表示を足す。
   正常な間も出続ける表示は、毎日読み飛ばす行になるためである。
3. 足した表示は、置き場所の表に1行足す。

## 毎日見る目での確認

画面を作る、直す変更は、実機のConsoleで次の手順で確かめる。
動くかと崩れないかだけでなく、毎日使う人の目で読む。

1. 経路の表(`console/src/app/screens.ts`)の全経路と、すべてのタブを開く。
2. 異常の無い状態で、上から読む。
   読み飛ばした行は、判断につながらない表示の候補とする。
3. 同じ数字、時刻、語が2か所に見えるものを探す。
   置き場所の表と照らし、置き場所以外の側を重複とする。
4. 候補ごとに、表示の要素ごとの3つの問いに答える。
   答えられないものは削る。

変更が実機に反映される前は、画面の描画テスト(`renderToStaticMarkup`)の出力を同じ目で読む。
反映された後に、実機で手順を行う。

## 表示の一覧

画面を作る、直す変更では、追加と変更をした要素ごとに、次の表を報告に載せる。
書けない要素は、削る。
残すときは、残す理由を表の下に書く。

| 表示の要素 | 誰が | 何を決めるか | 他の場所にあるか |
| --- | --- | --- | --- |
| 要件定義のタブの名前の件数 | 運用者が、画面を開くたびに | 要件定義を確かめに行くか | 無い |

レビューの扱いは、[レビューの規則](../.claude/skills/review-loop/rules.md)の「画面の表示」にある。
