# 残るリスク

Software Factoryが受け入れた残るリスクを、領域ごとの表にまとめる。
フローを変更する人と、セキュリティの変更をレビューする人が読む。
安全策の仕組みと理由は、各行の説明の列のリンク先にある。

## 表の読み方

IDは`R-<領域>-<連番2桁>`の形で、領域の略号は次の表のとおりである。
IDは、行を消しても使い回さない。
使い回すと、古いリンクが別のリスクを指すためである。
各節からは、IDをリンクの文字列にして、この文書の領域の見出しへリンクする。

各列の内容は次のとおりである。

| 列 | 内容 |
| --- | --- |
| リスク | 受け入れたリスク |
| 前提 | 受け入れが成り立つ前提 |
| 受け入れ理由 | 受け入れる理由と、リスクを抑える安全策 |
| 見直し条件 | 受け入れを見直す条件 |
| 説明 | リスクを書いた節 |

短いリスクは、元の文をそのまま表に載せる。
筋書き、根拠、測定のような長い説明を持つリスクは、説明を元の節に残し、表には要約を載せる。
元の文に無い欄は「元の文に無い」と書き、説明の節にあるものは「説明にある」と書く。

確かめていない前提と、後の作業で見直すものは、この表に載せず、元の節に書く。
新しい残るリスクは、この表に行を足し、元の節からはIDでリンクする。
