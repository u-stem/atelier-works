# dependabotの更新の内部仕様

dependabotが開いた依存の更新PRを、Factoryがどう選び、どう評価し、どの作業項目の状態で終えるかを定める仕様である。
`poll_dependabot`、フロー`f/factory/dependabot`とそのステップ、`lib/dependabot_*.ts`を変更する人が読む。
自動でマージする条件と残るリスクは[セキュリティ](../security.md#dependabotの更新の自動マージ)に、有効にする手順は[運用](../operations.md#dependabotの更新を設定する)に書く。

## 全体の流れ

処理は、PRを選ぶスケジュールと、1件のPRを処理するフローに分かれる。

| 部品 | 役割 |
| --- | --- |
| `poll_dependabot` | 10分ごとにPRを探し、フローと同じ収集とゲートで評価する。通ったPRだけ作業項目を作り、フローを起動する |
| `dependabot_prepare` | 事実を集め直してゲートを評価し、headのshaの作業ツリーに依存を隔離してインストールする |
| `dependabot_assess` | Claudeに影響を調べさせる。ツールは読み取りだけで、コマンドは実行させない |
| `dependabot_finish` | 結論を出し、マージ、所見の投稿、人に回すのどれかを行って作業項目を終える |

`dependabot_enabled`が偽の間は、スケジュールはGitHubとDBのどちらにも触れずに終わる。
起動の後で無効になったときは、フローの各ステップが作業項目を取り消し、GitHubへは書かない。

## PRの選び方

`poll_dependabot`は、照合を通ったオーナーごとに、次の条件でPRを検索する。

- dependabotのアプリが開いた
- 開いていて、draftでない
- baseが`main`である

検索の結果は、`poll_prs`と同じ許可リスト(`filterByRepoAllowlist`)で絞る。
`factory_repo`は、`owners`と`repo_allowlist`によらず通る。
検索は候補を絞るだけなので、PRを読み直して、開いていること、draftでないこと、baseが`main`であること、作者が`dependabot[bot]`であることを確かめる。

次のPRは選ばず、何もしない。

| 条件 | 理由 |
| --- | --- |
| 同じPRに、終端でない`pr_review`か`pr_fix`がある | 人が頼んだレビューと修正を先にする |
| 同じPRに、終端でない`dependabot`の作業項目がある | フローが動いている |
| 同じheadを処理済みである(`hasDependabotItemForHead`) | マージした後と人に回した後に、同じheadを処理し直さない |
| 公開の日数を待っていて、次に確かめる時刻の前である | 待つ間に、毎回registryの大きな応答を取り直さない |
| 同じheadで、フローが待ちで止まってから1時間たっていない | レート制限などの間に、周回ごとにフローを起動しない |

フロー自身が取り消した行は、処理済みに数えない。
対象の4つの注記は「作業項目の状態」の表にある。
それ以外の終端の行と、失敗した行は処理済みに数える。
取り消した理由が分からないheadと、マージや投稿の後に失敗しうるheadを、自動で処理し直さないためである。

## 評価と分岐

選んだPRは、フローの準備と同じ収集(`collectGateInput`)とゲート(`evaluateGate`)で評価する。
結果ごとの扱いは次のとおりである。

| 結果 | 扱い |
| --- | --- |
| 通った | 作業項目を`picked`で作り、フローを起動する |
| 人に回す | 作業項目を`picked`で作り、すぐ人の対応待ちにして、1回だけ通知する |
| 待つ | 作業項目を作らない。次の周回で評価し直す |
| PRが閉じた | 何もしない |

評価の途中でheadが動いたときは、待ちとして扱う。
公開の日数が足りないための待ちでは、公開から日数がたつ時刻を、スケジュールのstateに保存する。
その時刻までは、そのheadを評価しない。
headごとに保存するので、新しいheadは間引かない。

### 待ちの上限

PRを作ってから、公開の日数(`dependabot_min_published_days`)に7日を足した時間を超えて待ちが続けば、人に回す。
必須のチェックの失敗の放置やレート制限の連続で、いつまでも黙って待たないためである。
起点はPRを作った時刻なので、上限を過ぎたPRに新しいheadが来て待ちになると、すぐ人に回る。

### フローの待ちの抑止

スケジュールの評価が通っても、フローの準備やマージの直前の確認が待ちを返すことがある。
このとき、フローは作業項目を取り消して終える(注記`gate_waiting`)。
同じheadの取り消しから1時間たつまでは、フローを起動し直さない。
同じheadで取り消しが3回に達したら、人に回す。

### 処理済みの記録が消えたPR

`cleanup_db`は、保持期間(`retention_work_items_days`)を過ぎた終端の作業項目を消す。
作業項目の行はPRより後に作られるので、行が消えうるのは、作ってから保持期間を過ぎたPRだけである。
そのため、PRを作ってから「保持期間から1日を引いた日数」がたっていれば、評価せず人へ回す。
処理済みの記録が消えた後に、同じheadを自動で処理し直さないためである。
PR側に印を残す方法は採らない。
ラベルは人からFactoryへのトリガーに限り、PRに運用のコメントを書かない決まりがあるためである。

### 二重に起動しない

作業項目は、同じPRに終端でない`dependabot`の行があると作れない(部分一意インデックス`work_items_active_dependabot_key`)。
作れなかったときは、ほかの取得が先に始めたものとして何もしない。
スケジュールは`no_flow_overlap`で、前回の実行中は次の実行を飛ばす。
フローの起動に失敗したら、作業項目を失敗にして通知する。
失敗した行は処理済みに数えるので、同じheadは人が確かめるまで自動で起動しない。

## 作業項目の状態

状態の値と意味は[アーキテクチャ](../architecture.md#状態の一覧)の表にある。
dependabotの作業項目は、`picked`で始まり、次の終端のどれかで終わる。

| 状態 | 注記(`status_reason`) | 意味 |
| --- | --- | --- |
| `reviewed` | `merged` | マージした |
| `reviewed` | `impact_found` | 影響の所見を投稿した。修正のラベルは人が付ける |
| `cancelled` | `dependabot_disabled` | 処理の途中で無効になった |
| `cancelled` | `pr_closed` | PRが閉じたかマージされた |
| `cancelled` | `head_moved` | 処理の途中でheadが動いた |
| `cancelled` | `gate_waiting` | フローの収集かゲートが待ちを返した |
| `needs_human` | `dependabot <段階>: <詳細>`などの理由 | 自動では処理できず、人に回した |
| `failed` | フローの例外の理由など | 実行時エラーで止まった |

`cancelled`の4つの注記は、フローがそのheadを判断せずに止めたことを表す。
そのheadは、スケジュールが改めて評価する。

人に回す理由は、どの段階で止めたかを表す接頭辞で始まる。
接頭辞は、次の表の文字列に半角スペースを1つ続けた形である。
訳と次の操作は`pr_workflow_support.ts`の規則が決め、どの理由でも再実行を案内しない。

| 接頭辞 | 段階 |
| --- | --- |
| `dependabot poll:` | スケジュール(待ちの上限、保持期間、フローの待ちの回数、起動の失敗) |
| `dependabot collect:` | 事実の収集 |
| `dependabot gate:` | ゲート |
| `dependabot install failed:` | 隔離したインストール |
| `dependabot local check:` | インストールの後の確認 |
| `dependabot assess:` | 影響調査の実行 |
| `dependabot impact:` | 影響調査の結論 |
| `dependabot finish:` | マージや投稿の処理 |

## 照合と再実行

`poll_issues`の照合は、ほかの種別と同じく、dependabotの作業項目も扱う。
PRが閉じたことで取り消したときは、Discordに知らせない(`reconcileNotifies`)。
dependabotは置き換えたPRを自分で閉じるので、閉じたことは人の行動を求めないためである。
孤児として失敗にしたときは、ほかの種別と同じく知らせる。

`retry_work_item`は、dependabotの作業項目を再実行しない。
Consoleも再実行のボタンを出さず、PRを確かめて手でマージするか閉じるよう案内する。
新しいcommitが積まれると、スケジュールが新しいheadを別の作業項目で拾う。

## 定数

| 値 | 定義 | 意味 |
| --- | --- | --- |
| 10分 | `poll_dependabot.schedule.yaml` | スケジュールの周期 |
| 7日 | `WAIT_LIMIT_EXTRA_DAYS` | 待ちの上限で、公開の日数に足す日数 |
| 1時間 | `FLOW_WAIT_COOLDOWN_MS` | フローが待ちで止まった後に、起動を見送る時間 |
| 3回 | `MAX_FLOW_GATE_WAITS` | フローの待ちの取り消しが、この回数に達したら人に回す |
| 1日 | `RETENTION_MARGIN_DAYS` | 保持期間から差し引く余裕 |
